# Оркестратор подготовки к техническому собеседованию

## Цель

По исходному Markdown-файлу с вопросами готовить учебные ответы, сохраняя полный охват списка и прогресс на диске. В одном запуске обрабатывай ровно одну категорию: первую незакрытую категорию в порядке исходного файла.

Пользователь может попросить начать или продолжить, например: `/orchestrator`. Не полагайся на историю чата для определения прогресса: исходный файл и файлы категорий — источник истины.

## Обнаружение файлов и пути

1. Найди исходный файл Markdown с перечнем вопросов в рабочей папке. Обычно его имя содержит «вопрос» или «подготовк».
2. Если найдено несколько подходящих исходных списков и нельзя однозначно определить нужный — спроси пользователя, не выбирай наугад.
3. Создавай папку `ответы_для_собеседования/` рядом с исходным файлом.
4. Создавай в ней по одному файлу на категорию. Имя файла — понятный безопасный slug заголовка категории, например `Java.md`, `Selenide-Selenium.md`, `Testirovanie-API.md`. Сохраняй русские заголовки внутри файла.
5. Не перезаписывай существующие ответы. При продолжении прочитай их и дополняй только незавершённое.

## Выбор объёма за запуск

1. Прочитай исходный список и все существующие файлы категорий.
2. Найди первую по порядку исходного списка категорию, содержащую хотя бы один вопрос со статусом, отличным от `[x]`.
3. Обрабатывай только эту категорию. Не переходи к следующей категории в том же запуске, даже если текущая закончилась быстро.
4. Если все категории закрыты, сообщи, что работа завершена, и ничего не меняй.
5. Если исходный файл не найден, попроси пользователя добавить список. Не создавай выдуманный список.

## Статусы и восстановление после прерывания

- В исходном списке отмечай выполненный вопрос как `- [x] <исходный номер>. <исходный текст вопроса>`.
- В файле категории используй те же номера и статусы. Добавь чекбокс перед номером вопроса.
- Не меняй формулировки вопросов, их номера, порядок и принадлежность к категориям. Сохраняй исходный текст буквально, включая возможные опечатки; исправления исходника не входят в задачу.
- Для незавершённой работы допустим статус `[ ]`. Не ставь `[x]`, пока ответ полностью записан в файл категории.
- Сначала сохрани ответ в файл категории, затем отметь вопрос `[x]` в файле категории и в исходном списке. Если прерывание случилось между этими действиями, при продолжении проверь наличие полноценного ответа и синхронизируй статусы. Не дублируй ответ.
- Перед записью сверяй пару «категория + исходный номер» в обоих файлах. Номер сам по себе не уникален: он повторяется в разных категориях.
- Если файлы противоречат друг другу, содержимое и наличие ответа важнее отметки: проверь ответ, восстанови недостающую часть и приведи статусы к согласованному состоянию.
- Не помечай вопрос выполненным, если ответ пустой, содержит только заглушку или явно пропускает часть перечисленных тем.

## Файл категории

В начале файла создай заголовок категории и короткую заметку о формате. Для каждого вопроса сохраняй исходный номер и формулировку. Пример:

```markdown
# Java

> Ответы подготовлены для устного обсуждения на техническом собеседовании. Составные вопросы разделены на темы; исходные вопросы и нумерация сохранены.

## Вопросы и ответы

### [x] 1. Понимание принципов ООП и механизмов их реализации в Java (...)

#### a) Классы и объекты
**Ответ для собеседования**

...

#### b) Наследование
**Ответ для собеседования**

...
```

Не включай в файл категории вопросы из других категорий.

## Подготовка ответа

Для каждой самостоятельной темы готовь развёрнутый ответ, ориентированный примерно на 2–3 минуты устного объяснения. Это ориентир на каждую тему, а не на весь нумерованный вопрос: если вопрос составной, общий ответ может быть значительно длиннее.

По возможности включай:

1. Определение и объяснение принципа.
2. Важные отличия, ограничения и нюансы.
3. Конкретный пример, предпочтительно из Java, автоматизации тестирования или соответствующей категории.
4. Краткий вывод, который кандидат может произнести в конце ответа.

Правила полноты:

- Разбивай явно перечисленные самостоятельные темы составного вопроса на подпункты `a)`, `b)`, `c)` и далее. Отвечай на каждую отдельно; не прячь перечисленные темы в одной поверхностной фразе.
- Если вопрос проверяет одну тему, оставляй один ответ без буквенного подпункта.
- Не дели текст произвольно на подпункты, если аспекты тесно связаны и составляют одну тему.
- Сохраняй все исходные вопросы, включая дубли и похожие формулировки. Каждый такой вопрос получает отдельный ответ в своём исходном месте; не объединяй и не удаляй дубли.
- Учитывай область компетенции, подразумеваемую формулировкой. Не выдавай знание за практический опыт кандидата и не сочиняй личные истории. Можно дать нейтральный учебный пример.
- Если вопрос сформулирован как опыт или действие «на проекте», дай технический ответ о подходе и явно не утверждай, что пользователь лично это делал.
- Не растягивай ответ пустыми повторами. Полнота важнее точного количества слов.
- Точно различай похожие понятия и отмечай существенные оговорки. Не придумывай факты при неуверенности; пометь конкретное утверждение как требующее проверки и по возможности проверь по надёжной актуальной документации, если доступен веб-поиск.
- Примеры кода должны быть короткими, корректными и уместными. Объясняй, что они демонстрируют.

## Сабагенты

Используй сабагентов только если текущая среда действительно предоставляет такую возможность. Не предполагай, что конкретная модель или платформа умеет их запускать.

- Так как за один запуск готовится одна категория, не запускай сабагентов для всех категорий сразу.
- Для большой категории оркестратор может разделить независимые вопросы на небольшие непересекающиеся группы (например, по 3 вопроса) и делегировать их сабагентам.
- Запускай не более одного сабагента одновременно. Дождись его результата, проверь и сохрани его группу вопросов, и только после этого при необходимости запускай следующего сабагента.
- Передай каждому сабагенту точные формулировки и номера вопросов, категорию, правила ответа из этого скилла и требование вернуть результат с исходными номерами.
- Не делегируй одному и тому же вопросу нескольким агентам без причины. Не позволяй сабагентам параллельно редактировать общий исходный список или общий файл категории.
- Сабагенты возвращают подготовленный материал оркестратору. Только оркестратор проверяет полноту и согласованность, записывает единый файл категории и меняет статусы в обоих файлах.
- Если сабагенты недоступны, обрабатывай вопросы последовательно, при необходимости сохраняя прогресс после каждого вопроса.
- Не утверждай, что делегирование произошло, если инструментального вызова не было.

## Порядок выполнения

1. Найди и прочитай исходный список и существующий файл выбранной категории.
2. Построй внутреннюю сверку всех вопросов категории по идентификатору «заголовок категории + номер».
3. Для каждой незакрытой записи подготовь ответ по правилам выше. Проверь, что покрыты все перечисленные подтемы.
4. Если используешь сабагентов, собери их результаты и проверь на пропуски, дублирование внутри ответа, противоречия и несоответствие вопросу.
5. Запиши ответы в правильном порядке в файл категории. Сохрани исходный вопрос, разбиение на подпункты и ответ.
6. Отметь полностью обработанные вопросы `[x]` в файле категории и исходном списке.
7. Повторно проверь выбранную категорию: число исходных вопросов соответствует числу вопросов в файле категории; у каждого `[x]` есть содержательный ответ; статусы синхронизированы; ничего не пропущено или не объединено.
8. Если закончилась категория, сообщи, что она завершена и следующий запуск возьмёт следующую незакрытую категорию. Не обрабатывай её сейчас.

## Отчёт пользователю

После запуска кратко сообщи:

- какую категорию обрабатывал;
- какие номера завершены, а какие остались незавершёнными;
- путь к файлу категории;
- путь к обновлённому исходному списку;
- использовались ли сабагенты (только если действительно использовались);
- завершена ли категория и что будет выбрано при следующем запуске.

Если работа прервалась или не удалось полностью завершить категорию, честно укажи это. Оставь корректные статусы и файл в состоянии, пригодном для продолжения.
